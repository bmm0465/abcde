# 02. 데이터 모델

허브 공용 스키마와 앱별 스키마의 경계, 권한 규칙, 사용량 통제의 흐름.
정본은 `supabase/migrations/` 다. 이 문서는 그 의도를 적는다.

## 1. 원칙

- **한 사람 = auth.users 한 행 = profiles 한 행.** 역할·승인·한도는 profiles 에만 있다.
- **앱별 테이블은 `<slug>_` 접두어.** `aidapel_test_results`, `aieewa_questions` 처럼. 허브 테이블은 접두어 없음.
- **RLS 가 최종 방어선.** 서버 코드가 실수해도 DB 가 남의 행을 내주지 않는다.
- **service_role 은 세 곳만**: 사용량 기록, 속도 제한 카운트, 관리자 스크립트.

## 2. 허브 테이블

### profiles

| 컬럼 | 뜻 |
|---|---|
| `id` | auth.users.id |
| `role` | `admin` · `teacher` · `student` · `guest`(가입 직후) |
| `status` | `pending`(가입 직후) · `approved` · `suspended` |
| `display_name` `affiliation` `purpose` | 가입 폼. 본인이 고칠 수 있는 유일한 컬럼들 |
| `monthly_budget_usd` | null 이면 서버 기본값. 관리자만 |
| `approved_at` `approved_by` | 승인 기록 |

- 가입 트리거 `handle_new_user` 가 만든다. `hub_admin_emails` 에 있는 주소면 `admin/approved` 로.
- `protect_profile_columns` 트리거: 사용자 세션에서 관리자가 아니면 role/status/budget/approved/email 을 못 바꾼다.
- 정책: 본인 읽기·쓰기, 관리자 전체 읽기·쓰기.

### hub_admin_emails
가입 즉시 관리자가 될 주소. 정책 없음(service_role 전용). `npm run admin:promote` 로 넣는다.

### app_access (user_id, app_slug)
역할과 무관하게 특정 앱을 열어 주는 예외. `canUseProject()` 가 역할 다음에 본다.

### usage_events
LLM·STT·TTS 호출 1건 = 1행. `est_cost_usd` 는 `src/lib/usage/pricing.ts` 의 단가표로 서버가 계산.
- `monthly_usage_usd(uid)` — KST 기준 이번 달 합계. 한도 검사에 쓴다.
- `usage_monthly` 뷰 — 관리자 화면. `security_invoker` 라 RLS 가 그대로 적용된다.

### api_requests
속도 제한용 로그. 분당 N회. 정책 없음(service_role 전용). 오래된 행은 나중에 cron 으로 지운다.

## 3. 권한 판단 순서 (`src/lib/auth/access.ts`)

```
project.use === 'public'      → 허용
미로그인                      → 로그인
status === 'suspended'        → 차단
role === 'admin'              → 허용
status !== 'approved'         → 승인 대기
project.use === 'login'       → 허용
project.use 에 role 포함      → 허용
app_access 에 slug 포함       → 허용
그 외                         → 권한 없음
```

세 겹으로 같은 규칙을 적용한다: `src/proxy.ts`(쿠키만, 낙관적) → 화면·서버 액션·API(`guards.ts`, `authorize.ts`) → RLS.

## 4. LLM 호출 한 번의 흐름

```
클라이언트 → /api/<slug>/…
  guardLlmRequest(slug, route)
    authorizeApi      로그인 · 프로필 · canUseProject
    assertRateLimit   api_requests 60초 창 카운트 → 넘으면 429 rate_limited
    assertWithinBudget monthly_usage_usd ≥ 한도 → 429 budget_exceeded
  제공자 호출 (키는 서버 환경 변수)
  recordUsage(...)    usage_events insert (service_role, 실패해도 응답은 깨지지 않음)
```

## 5. 앱별 스키마 계획

### AIDAPEL (`aidapel_*`)
기존 9개 마이그레이션을 새 프로젝트에 맞춰 통합한다. 핵심: `aidapel_students`(user_id → profiles, teacher_id, class_name, student_number, grade_level), `aidapel_test_results`, `aidapel_feedback`, `aidapel_transcription_reviews`, 문항 생성 워크플로 테이블, Storage 버킷 `aidapel-audio`.
- 기존 `user_profiles.role` 은 허브 `profiles.role` 로 흡수. 학생은 교사가 만들고(`created_by`), 교사는 자기 학생만 본다.

### AIEEWA (`aieewa_*`)
`aieewa_questions`, `aieewa_student_answers`, `aieewa_evaluation_sessions`, `aieewa_documents`, `aieewa_document_chunks`(pgvector 1536). 모든 행에 `owner_id`(만든 교사) 를 붙여 RLS 를 건다. RAG 코퍼스(교과서 PDF 청크)는 로컬 시드 스크립트로만 넣고 저장소에는 두지 않는다.
