로컬에서 띄우고, Supabase 를 연결하고, Vercel 에 올리는 순서.

> **현재 구성 (2026-09-13 적용 완료)**
>
> ABCDE 는 **AIEEBSS** Supabase 프로젝트(`ltiwdytxijspfwbesgfz`)를 AIDAPEL 파일럿과 **함께** 쓴다.
> 무료 플랜은 활성 프로젝트가 2개까지인데 그 둘이 AIEEBSS 와 mdg-new(LOOP, 학기 진행 중)라,
> 새 프로젝트를 만들 자리가 없었다. 자세한 판단은 아래 §0.
>
> 적용 완료: 마이그레이션 3개, 관리자 이메일 등록, 리다이렉트 URL, `.env.local`.
> 남은 것: `OPENAI_API_KEY` 입력, 가입 후 동작 확인, Vercel 배포.

## 0. 왜 프로젝트를 공유하는가, 그리고 무엇을 막아 놓았는가

**mdg-new(LOOP)와는 공유할 수 없었다.** 세 가지가 정면으로 부딪힌다.

1. LOOP 에 이미 `public.profiles` 가 있고 마이그레이션 19개와 40개 넘는 표가 외래키로 물려 있다. 허브의 `create table public.profiles` 는 첫 줄에서 실패한다.
2. `handle_new_user()` 가 양쪽에 있고 허브 쪽은 `create or replace` 라 **조용히 덮어쓴다.** 그러면 LOOP 의 신규 가입이 통째로 깨진다.
3. 스키마를 나눠도 `auth.users` 는 프로젝트에 하나뿐이다. 공개 사이트에서 비밀번호를 재설정하면 같은 이메일을 쓰는 LOOP 수강생의 로그인 비밀번호가 바뀐다. LOOP 은 진행 중인 학기의 성적 산출 도구다.

**AIEEBSS 와는 기계적 충돌이 없다.** AIDAPEL 은 `user_profiles` 를 쓰고 허브는 `profiles` 를 쓴다. 표·함수·트리거 이름이 하나도 겹치지 않고, AIDAPEL 에는 `auth.users` 트리거가 없다.

**대신 남는 위험 하나를 코드로 막았다.** 이 데이터베이스에는 AIDAPEL 파일럿의 초등학생 이름과 음성 녹음이 있다. `service_role` 키는 프로젝트 단위라 키가 하나 새면 그 데이터까지 전부 열린다. 그래서 런타임에 service_role 이 필요했던 두 가지(사용량 기록, 속도 제한)를 `security definer` 함수로 옮겼다(`20260913010000` 마이그레이션).

> **결과: Vercel 환경 변수에 `SUPABASE_SERVICE_ROLE_KEY` 를 넣지 않는다.**
> 배포된 앱은 그 키 없이 돈다. 키가 필요한 곳은 로컬 스크립트 하나뿐이다(`npm run aieewa:seed`).

알아 둘 것 두 가지.

- `auth.users` 에 AIDAPEL 파일럿 계정 115개가 이미 있다. 허브의 가입 트리거는 새 INSERT 에만 반응하므로 그 계정들은 ABCDE 프로필을 갖지 않는다.
- 앞으로 교사가 AIDAPEL 학생 계정을 새로 만들면 허브 트리거가 함께 돌아 `profiles` 에 `pending` 행이 생긴다. 관리자 화면의 승인 대기 목록에 나타나지만 승인하지 않으면 아무것도 할 수 없다.
- 데이터베이스 용량 500MB 를 AIDAPEL 과 나눠 쓴다. AIEEWA 코퍼스를 크게 넣기 전에 대시보드에서 현재 사용량을 볼 것.

## 1. 로컬 실행 (Supabase 없이)

```bash
npm install
npm run dev
```

http://localhost:3000 — 허브 화면(프로젝트·기록·소개)은 Supabase 없이도 열린다. 상단 바에 "인증 미설정" 이 보이면 정상이다.

## 2. Supabase 연결 (이미 되어 있음 — 다시 할 때의 절차)

`.env.local` 은 이미 만들어져 있다. 아래는 다른 프로젝트에 새로 붙일 때의 절차다.

1. 프로젝트를 고르거나 만든다. 새로 만든다면 리전은 `Northeast Asia (Seoul)`, DB 비밀번호는 비밀번호 관리자에 저장.
2. **Project Settings → API Keys** 에서 값을 복사한다.
   - Project URL → `NEXT_PUBLIC_SUPABASE_URL`
   - Publishable key(`sb_publishable_…`) → `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (구형 프로젝트는 anon key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`)
   - Secret key 는 **웹 앱에 필요 없다**(§0). `npm run aieewa:seed` 를 돌릴 때만 `SUPABASE_SERVICE_ROLE_KEY` 에 넣는다.
3. `.env.example` 을 복사해 `.env.local` 을 만들고 값을 채운다.

### 2.1 인증 설정 (Authentication → 왼쪽 메뉴)

| 항목 | 값 |
|---|---|
| **Sign In / Providers → Email** | 켜기. **Confirm email** 켜기(가입 시 인증 메일). |
| **URL Configuration → Site URL** | 운영 도메인(예: `https://abcde-projects.vercel.app`). 로컬 개발 중에는 `http://localhost:3000` |
| **URL Configuration → Redirect URLs** | `http://localhost:3000/auth/callback`, `https://<운영 도메인>/auth/callback`, 그리고 Vercel 프리뷰를 쓰면 `https://*-<팀>.vercel.app/auth/callback` |
| **Emails → Templates** | 기본 템플릿도 동작한다. 한국어로 바꾸려면 Confirm signup / Reset password 두 개만 손보면 된다. |
| **Rate Limits** | 기본값 유지. 무료 플랜의 내장 메일은 시간당 소량이라, 사용자가 늘면 **SMTP(Resend 등)** 를 연결한다. |

### 2.2 마이그레이션 적용

방법 A — SQL 편집기(가장 단순):
1. Dashboard → **SQL Editor** → New query.
2. `supabase/migrations/20260912000000_hub_core.sql` 내용을 붙여 넣고 Run.
3. 이후 파일도 파일명 순서대로 같은 방식.

방법 B — CLI(반복 작업에 유리):
```bash
npx supabase login                       # 브라우저에서 토큰 발급
npx supabase link --project-ref <ref>    # ref 는 Project Settings → General
npm run db:push                          # supabase/migrations 를 순서대로 적용
```

### 2.3 관리자 지정

`bmm0465@gmail.com` 은 이미 등록되어 있다. 이 주소로 가입하면 즉시 관리자(승인됨)가 된다.

다른 주소를 추가하려면 둘 중 하나를 쓴다.

```bash

```

service_role 키를 쓰고 싶지 않으면 SQL 편집기에서 한 줄이면 된다.

```sql
insert into public.hub_admin_emails (email) values ('you@example.com') on conflict (email) do nothing;
```

## 2.5 AIEEWA 쓰기

문항 생성과 채점에는 OpenAI 키가 필요합니다. `.env.local` 과 Vercel 환경 변수에 `OPENAI_API_KEY` 를 넣으세요.

### RAG 코퍼스 넣기 (선택이지만 권장)

코퍼스가 비어 있어도 문항은 만들어집니다. 다만 교과서·성취기준에 근거하지 않습니다.

1. 저장소 루트에 `corpus` 폴더를 만들고 교육과정 자료를 넣습니다. `.pdf` `.txt` `.md` 를 읽습니다.
   - 이 폴더는 `.gitignore` 에 있습니다. **원본은 절대 커밋되지 않습니다.**
   - 서버에는 텍스트 청크와 벡터만 올라갑니다. PDF 파일 자체는 올라가지 않습니다.
2. 적재합니다.

```bash
npm run aieewa:seed
```

같은 파일을 다시 넣으면 그 문서의 청크만 지우고 다시 만듭니다. 파일 이름이 곧 문서 id 라, 이름을 바꾸면 새 문서가 됩니다.

스캔한 PDF(그림으로만 된 것)는 텍스트가 없어 건너뜁니다. OCR 을 먼저 돌려야 합니다.

### 비용 감각

`AIEEWA_MODEL` 기본값은 `gpt-4o` 입니다. 대략 문항 한 건 생성에 0.05~0.15달러, 답안 한 건 채점에 기본 채점은 0.01~0.03달러, 근거 채점(AAS)은 검증과 재채점까지 해서 0.03~0.10달러쯤 듭니다. 사용자별 월 한도는 관리자 화면에서 조정합니다. 더 싼 모델로 바꾸려면 `AIEEWA_MODEL` 을 설정하고 `src/lib/usage/pricing.ts` 의 단가표에 그 모델이 있는지 확인하세요.

### 함수 실행 시간

생성과 채점 라우트는 `maxDuration = 60` 입니다. Vercel Hobby 의 상한이 60초입니다. Pro 라면 `src/app/api/aieewa/*/route.ts` 에서 300 까지 올릴 수 있습니다.

## 3. Vercel 배포

1. GitHub 에 저장소를 올린다(공개). `npm run check:secrets` 가 통과하는지 먼저 본다.
2. https://vercel.com/new → 저장소 import. Framework 는 Next.js 자동 인식.
3. **Environment Variables** 에 다음만 넣는다. `SUPABASE_SERVICE_ROLE_KEY` 는 **넣지 않는다**(§0).
   - `NEXT_PUBLIC_SITE_URL` (운영 도메인)
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - `OPENAI_API_KEY`
   - 필요하면 `DEFAULT_MONTHLY_BUDGET_USD`, `RATE_LIMIT_PER_MINUTE`, `AIEEWA_MODEL`
4. Deploy. 끝나면 Supabase **Authentication → URL Configuration** 에서
   Site URL 을 운영 도메인으로 바꾸고, Redirect URLs 에 `https://<운영 도메인>/**` 을 추가한다.
   `http://localhost:3000/**` 은 개발용으로 남겨 둔다.
5. GitHub 에 푸시할 때마다 자동 배포된다. PR 은 프리뷰 URL 이 생긴다.

## 5. 자주 막히는 곳

- **가입 메일이 안 온다** → Authentication → Logs 확인. 무료 플랜 내장 메일은 시간당 한도가 작다. SMTP 연결.
- **인증 링크를 누르면 로그인 화면으로 돌아온다** → Redirect URLs 에 `/auth/callback` 이 정확히 있는지, Site URL 이 현재 도메인인지 확인.
- **/admin 이 404** → 그 계정이 admin/approved 가 아니다. `hub_admin_emails` 에 넣은 뒤 **다시 로그인**해야 반영된다.
- **사용량이 "불러오지 못했습니다"** → `monthly_usage_usd` 함수가 없다. 마이그레이션이 다 적용됐는지 확인.
- **채점·생성이 "지금은 요청을 처리할 수 없습니다"** → `record_usage` / `consume_rate_limit` 함수가 없다. `20260913010000` 마이그레이션을 적용할 것.
- **빌드에서 `bg-blue-500` 같은 클래스가 깨진다** → 의도된 것. `globals.css` 의 토큰을 쓴다.
